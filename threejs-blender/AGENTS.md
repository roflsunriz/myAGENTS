# Three.js / Blender 制作の AGENTS.md

## 最優先の目的

**リファレンス画像が渡されたら、テクスチャやディテールを勝手に省略せず、参照とそっくり同じに見える成果物を作る。**

形状、比率、色、模様、凹凸、材質、細部、陰影までを再現対象とする。「雰囲気が似ている」「主要な形はできた」「簡略版として完成」を依頼の達成と扱わない。実装しやすさ、作業時間、コード量、ポリゴン数を理由に、再現対象を無断で減らさない。

このファイルは、Three.js または Blender で参照画像からモデル・シーンを制作する場合の追加指針である。作業前に、対象プロジェクトの共通ルール（`COMMON-AGENTS.md` 等）、ローカル `AGENTS.md`、このファイルを全文読む。手段は対象プロジェクトと依頼に合わせ、再現度を保つために必要なモデリング、画像テクスチャ、プロシージャル表現、シェーダー等を選ぶ。

## 省略・置き換えによる完成扱いを禁止する

- 木目、布目、縫い目、毛髪、傷、汚れ、印刷、刻印、装飾、金具、接合部等を、目立たない・面倒・実装が難しいという理由で消さない。
- テクスチャのある表面を単色にする、固有の模様を汎用ノイズや適当な繰り返し模様にする、参照固有の形を粗い箱・球・円柱の組み合わせで代用する等で済ませない。基本形状だけで参照を正確に表せる場合は、その手法を使ってよい。
- 髪を滑らかな塊にする、衣服のしわを消す、材質を一律にプラスチック状にする等、参照固有の見た目を失う置き換えをしない。参照自体が単純化された表現なら、その形と省略の仕方を正確に再現する。
- 描画できない材質・テクスチャ・部品を非表示にしたり、代替色へ黙って置き換えたり、読み込みエラーを握りつぶしたりして成功扱いしない。
- 暗い照明、強い白飛び、ぼかし、被写界深度、遠景、都合のよいカメラや切り抜きで不足を隠さない。
- 参照画像を平面に貼っただけのものや、レンダリング後に画像を重ねて取り繕ったものを、3D の再現として提出しない。投影テクスチャやデカールを使う場合も、必要な立体形状と視点変更時の整合を保つ。
- 手続き生成だけ、外部テクスチャ禁止、ローポリ等の制約を、指示がないのに自分で設けない。必要な外観を維持できる手法を自律的に選ぶ。
- 最適化は見た目を比較して行う。性能・容量の制約と忠実度が両立しない場合は、計測と代替手段の検討を行い、ユーザーが許可するまで省略を既定解にしない。

## 描き始める前に参照を分解する

1. 参照の実画像を開き、全体と拡大した各部を観察する。説明文や記憶だけで作り始めない。複数の画像がある場合は、視点と対象部位の対応を整理する。
2. ユーザーの指定から再現対象の範囲を確定する。変更指示がなければ、ポーズ、表情、衣装、装飾、配色、作風を維持する。
3. 画像上の端点、境界、代表点を取得し、全体寸法、部位比率、配置、シルエット、隙間、重なりを測る。基準長と測定箇所を残し、目分量の値は推定と記載する。
4. カメラの向き、投影、画角、対象の画面内サイズ、光の方向・広がり、背景や反射の影響を分析する。カメラの違いを、体型や形状の誤りと混同しない。
5. 下表を出発点に、対象固有の特徴を漏れなく追加する。人、動物、製品、建築、小物等の種類に応じて項目を変え、代表的な数項目だけで全体を代用しない。

| 観点 | 記録して再現する内容 |
| --- | --- |
| 立体形状 | 輪郭、部位の縦横比・厚み、面の曲率、角・面取り、穴、溝、部品の数と接続、左右差、部位間の隙間 |
| 表面の図柄 | 色面、模様、文字・ロゴ・刻印の形と配置、柄の向き・寸法・密度、境界、固有の傷や汚れ |
| 表面の凹凸 | 布目、木目、毛束、縫い目、しわ、段差、微細な凹凸の深さ・方向・間隔 |
| 材質 | 粗さ、光沢、金属感、反射、透過、透明度、発光、素材間の違い、部位ごとの変化 |
| 描き方・光 | 写実・イラスト等の表現、輪郭線、陰影の段階、ハイライトの形、影の硬さ、質感の粒度 |

特徴ごとに「参照画像の箇所」「観測内容と測定値」「再現方法」「実装箇所・使用素材」「比較結果・残る差」を記録する。既存の制作メモや検証文書にまとめてよい。一覧を作っただけで済ませず、各項目を実際の形状・マテリアル・テクスチャへ接続する。

## 形状とテクスチャを適切な手段で再現する

- 測った比率と位置を、メッシュ、カーブ、モディファイア、描画パラメータ等へ反映する。大形状から細部へ段階的に作り、仮形状を最終品質として残さない。
- 輪郭、厚み、視差、影、部品同士の重なりに影響する形は、それらを再現できる立体形状や変位として作る。必要な立体を色やノーマルマップだけで代用しない。
- 表面の細部には、画像テクスチャ、プロシージャル材質、法線・バンプ・変位、デカール等から適切な手段を選ぶ。同じ見た目を実現できる表現方法の選択と、見た目そのものの省略を区別する。
- 模様は種類だけでなく、位置、向き、大きさ、形、密度、色、規則性・不規則性を合わせる。ノイズを足しただけで、木目、織り目、傷等を再現したと判断しない。
- UV の歪み、継ぎ目、左右反転、繰り返し周期、テクスチャの解像度を確認する。縮小・圧縮・フィルタリング後も、参照で判別できる模様や文字が残ることを確認する。
- 色だけでなく、粗さ、反射、凹凸、透過等の必要な表面特性を反映する。不要なマップを機械的に増やす必要はないが、単色マテリアルで表せない特徴を省略しない。
- 写真からテクスチャを作る場合は、表面の図柄と撮影時の影・反射を見分け、照明との二重掛けで不自然になっていないか確認する。識別できない細部を勝手な模様で埋めない。
- イラストの参照へ不要な写実表現を加えたり、写実的な参照を作りやすいトゥーン表現へ変えたりしない。「より美しくする」ための装飾・質感追加も、忠実再現の代わりにしない。

## 同じ視点でレンダリングし、比較して直す

1. 参照画像に対応する検証用カメラを設定し、向き、投影、画角、構図、画像の縦横比・寸法を合わせる。必要な照明・背景・色の表示条件も記録する。
2. 大形状、部位形状、テクスチャ・材質、細部・仕上げの各段階で実際にレンダリングする。コードやシーン設定の確認だけで見た目を判断しない。
3. 参照とレンダリングを並べ、同じ座標で半透明重ね合わせ・輪郭比較・差分表示を行う。全体に加え、顔、髪、素材の境界、模様、刻印、接合部等を、同じ箇所・倍率で拡大比較する。生成した比較画像は実際に開いて見る。
4. 比較のために制作画像だけを部位別に伸縮・ワープしたり、細部が消える解像度まで縮小したりしない。カメラや表示条件を調整した場合は条件を更新し、関連箇所を再比較する。
5. 差を、カメラ、形状、部位比率、UV、図柄、材質、照明、色管理、読み込み不良等に分け、原因のある箇所を修正する。輪郭が合っただけで材質や表面の差を残さない。
6. 特徴一覧の全項目を照合し、不足、別の形への置き換え、過度な単純化を解消する。小さくても識別できる固有の特徴を、全体の類似度スコアに埋もれさせない。
7. 最終版は参照と同等に細部を判断できる寸法と実際の利用時の表示で確認する。次節の多方向確認を必須とし、複数の参照視点がある場合は全視点を照合する。
8. 最後の修正、ベイク、書き出し、最適化の後に、提出する実ファイルから再度レンダリングして比較する。以前の成功画像で最終成果物を検証したことにしない。

参照画像に圧縮ノイズやアンチエイリアスがある場合は、意図した形・表面の差と区別する。比較の基準は作業前に参照の解像度と要求精度から定め、合格のために後から緩めない。根拠のない一致率や「完全一致」を報告せず、識別できる未解消の差があれば修正を続ける。

## 3方向・4方向・5方向から破綻を確認する

参照に一致する一方向だけで合格にしない。制作途中から確認方向を3方向、4方向、5方向へ増やし、最終版は最低5方向から実際にレンダリングして確認する。参照画像との一致確認と、多方向からの立体・表面の整合性確認を両方行う。

| 段階 | 確認する方向 | 主な確認対象 |
| --- | --- | --- |
| 3方向 | 対象の正面・左側面・右側面 | 幅と厚み、部位比率、左右の形状、奥行き、部品の接続 |
| 4方向 | 3方向に背面を追加 | 背面の作り残し、裏側の穴、接合部、前後での材質・模様の連続性 |
| 5方向 | 4方向に上方または下方からの斜め視点を追加 | 上面・下面、入り組んだ部分、重なり、貫通、浮き、死角の細部 |

- 方向は対象の正面を基準に定義し、上方・下方は構造の不確かな箇所を確認できる方を選ぶ。両方や追加の斜め視点が必要なら5方向を超えて確認する。方向数を満たしても死角に未確認の部位が残る場合は完了にしない。
- 参照と同じ視点が上記に含まれない場合は、その比較用視点も追加する。参照にない方向では立体・材質の整合を確認し、推定した背面等が原物と一致すると断定しない。
- 同一のモデル・ポーズ・材質・シーン状態を使い、カメラを回り込ませて確認する。方向ごとに形状や部品の表示を変えて取り繕わない。同じ方向の拡大、画像の左右反転、わずかな角度差を別方向として数えない。
- 全方向で、シルエット、厚み、接合、貫通・浮き・隙間、欠けた面・法線の反転、UV の継ぎ目・伸び、模様の途切れ、テクスチャ・透過・材質の欠落を確認する。必要な箇所は拡大し、質感を確認できるレンダリングを使う。
- 方向間も連続的に視点を移動し、途中の角度だけで面や部品が消える、重なり順が崩れる、表面がちらつく等の問題を確認する。問題が見える角度を追加の確認視点として残す。
- 各方向の画像に方向名を付け、再現できるカメラ位置・向きと確認結果を保存する。画像を生成しただけで済ませず、全方向を実際に開き、並べて確認する。
- 一方向で見つかった問題を修正した後は、参照との比較と全ての確認方向を再レンダリングして、別方向に退行がないことを確認する。最終修正・書き出し・最適化後にも、使用先で同じ確認を行う。
- 一方向でも未解消の破綻がある場合は未完了とし、形状・材質等の原因を修正する。確認していない方向を「破綻なし」に含めない。

## 使用先で質感と細部が残ることを確認する

### Three.js

- 実際のページ・シーンをブラウザで開き、モデル、マテリアル、全テクスチャの読み込み完了後に検証する。ネットワーク・コンソールの失敗、欠落したマップ、代替材質を確認して修正する。
- テクスチャの色空間、色以外のデータの扱い、出力の色変換、トーンマッピング、露出等を確認する。色管理の誤りを照明の強弱だけで補正しない。設定は[公式の色管理説明](https://threejs.org/manual/pages/color-management.html)を参照し、使用中の版と照合する。
- 実際に使うカメラ距離・表示寸法で、細部、テクスチャの鮮明さ、透過、影、反射を確認する。別のビューアで表示できたことだけで完了にしない。

### Blender

- 材質とテクスチャを確認できる表示および最終レンダリングで検証し、Solid 表示やマテリアル未反映のプレビューだけで完成にしない。
- 編集した画像・依存素材も保存し、必要な素材を同梱するか、対応するものを `.blend` にパックして保存する。保存した成果物を開き直し、作業中のメモリや納品対象外の絶対パスに依存せず再現できることを確認する。
- 全ての外部データがパック可能だと仮定せず、素材ごとに保存・同梱を確認する。[公式の Packed Data の説明](https://docs.blender.org/manual/en/latest/files/blend/packed_data.html)を参照し、操作は使用中の版で確認する。

### Blender から Three.js 等へ受け渡す場合

- 使用する形式と読み込み先が、必要な材質・形状表現に対応するか確認する。Blender 内の見た目がそのまま書き出されると仮定しない。glTF を使う場合は[公式マニュアル](https://docs.blender.org/manual/en/latest/addons/scene_gltf2.html)を参照し、使用中の版と読み込み先が対応する表現を確認する。
- そのまま移せないノード、プロシージャル材質、変位、毛髪等がある場合は、必要なベイク、形状化、読み込み先での材質実装等を行って外観を保持する。非対応という理由だけで削除しない。
- 書き出した実ファイルを使用先へ読み込み、形状、テクスチャ、UV、材質、透過、陰影を再比較する。受け渡しが要求されている場合、元の `.blend` だけが正しくても未完了である。

## 見えない部分と実行不能を正直に扱う

- 一枚の画像から、隠れた背面、内部構造、微細な柄や材質の真値を確定したと主張しない。複数の参照や提供素材を先に調べ、観測できる範囲と推定する範囲を分ける。
- 推定箇所は、見えている形状と材質に矛盾しないよう作る。結果を大きく左右する不足は追加情報で解消する。不可視部分があることを、見えているディテールまで省略する理由にしない。
- 使用環境の制限、素材不足、レンダリングの障害で再現できない場合は、必要な機能を消して成功表示にせず、原因と代替手段を調べる。自力で解消できない場合は、実行可能な作業を終え、未達箇所、根拠、再開条件を具体的に示す。

## 完了条件と提出

- 参照で確認できる形状、テクスチャ、細部、材質が実装され、特徴一覧に実装漏れ・無断の省略がない。
- 参照と同じ視点の全体比較と、細部の拡大比較を行い、残っていた差を修正している。最終画像だけでなく、制作途中から比較を繰り返している。
- 3方向・4方向・5方向へ段階的に確認を進め、最終版を最低5方向と必要な追加視点で検証している。各方向に未解消の形状・テクスチャ・材質の破綻がなく、方向間の視点移動も確認している。
- 提出するモデル・シーン・コードと必要な素材を実際の使用先で開き直し、質感や細部の欠落がない。依頼に含まれる書き出し・受け渡しも検証している。
- 成果物に加え、参照との比較画像、方向名付きの多方向画像とカメラ情報、特徴ごとの対応・確認結果、再表示に必要な手順を確認できる。記録は既存文書や一つの比較シート等へまとめてよい。
- 推定した箇所、残る差、未検証事項を明記し、未達の状態を「そっくり同じ」「完全再現」「完成」と呼ばない。

**「省略したことを報告した」は「省略してよいと許可された」ではない。観測できる特徴を再現し、実際の表示で確かめるところまでを仕事とする。**
